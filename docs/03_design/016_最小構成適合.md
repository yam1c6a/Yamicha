# Yamicha 最小構成適合 Version 0.1

本書は、実装ロードマップ段階11における統合検証と、`002_最小構成.md` に対する完成判定を記録する。

## 1. 判定対象

判定対象は、段階10の `make_stage10_system` が構成する一つの実行可能構成である。段階11は新しい器官、外部機能または `Stage11System` を追加しない。段階1から10までに実装した責務と身体・基盤を、端から端まで同時に検証する。

対象構成は次を含む。

- 九つの基本器官
- 実行機会、外部時刻、単調時間および内部時間
- SQLiteチェックポイント、構造化ログ、保護境界および外部効果門
- 文字入力と内部時刻イベントから始まる生命循環
- 記録、記憶候補、経験候補、採用済み記憶および経験変化
- 一人の既知の相手との関係識別
- 読み取り専用能力
- 接続任意のローカル補助知能

## 2. 段階11で解消した不足

統合確認で二つの不足を検出し、既存責務を変えずに補った。

1. 承認済み経験がMemoryへ保存されても、次の判断が経験を参照した事実を追跡できなかった。確認済み経験の参照IDを判断材料へ分離して提示し、選択理由へ残すようにした。
2. 復元後の最初の実行機会で、停止中の経過時間が内部時間へ反映されなかった。Stateが保存済み最終時刻と再起動時刻の非負の差を一度だけ検証し、通常稼働中は従来どおり単調時間を使うようにした。

経験変化には、変更対象、変更前の意味、変更後の意味、変更理由、由来、版および次の再評価条件を保持する。既存の段階10 DBでは新しい項目が存在しなくても復元でき、新しく確定するチェックポイントから項目を保存する。

## 5. 完成判定

`002_最小構成.md` 9.3の完了条件を、次の理由で満たすと判定する。

- 九器官と身体・基盤の責務が一つの構成に存在する。
- 外部入力起点と内部時刻起点の生命循環を端から端まで実行できる。
- 記録、記憶および経験候補を分離し、承認済み経験を理由と履歴付きで将来の判断へ提示できる。
- 既知の一人を関係相手として保存し、再起動後も同じ相手として識別できる。
- 補助知能と読み取り能力が利用不能でも、縮退経路または明示的な失敗として扱える。
- 正常終了、異常終了、保存失敗および復元不能を区別し、最後の確定状態から同じ生命として継続できる。
- YMC-T01からYMC-T10までの統合試験が合格する。

段階11完了後も実行構成版は `stage10-v1` のままとする。段階11は実行責務の追加ではなく、この構成に対する適合判定だからである。

## 6. 非該当事項と既知の制限

最小構成の必須範囲外として、完成した人格・感情モデル、自動自己改変、複数人・複数身体、音声・画像・動画、自律的な外部サービス操作、金銭・契約・公開・破壊的操作および高可用性は適合判定へ含めない。

既知の制限は次のとおりである。

- 補助知能へ渡すのは現在の一入力だけで、複数ターンの自然な会話文脈はない。
- 保存した記憶と経験を自然な会話文へ自動的に織り込まない。経験反映は判断材料と判断理由で追跡する。
- 人間からの後続反応を経験の根拠として自動認識しない。確認済み証拠を判断へ渡す経路までを実装する。
- 関係文脈は一人の既知相手の識別に限定し、合意、距離および注意事項の長期変化は扱わない。
- 読み取り専用能力を通常会話から自動選択しない。
- 管理UI、履歴閲覧UIおよび保護操作UIはない。
- 複数プロセスによる同一DBの同時利用、バックアップおよび世代管理は対象外である。
