# Yamicha 会話文脈 Version 0.1

本書は、実装ロードマップ段階12における複数ターンの会話文脈、その所有、補助知能への限定提示、永続化および明示的な切替を定める。

## 1. 目的と範囲

段階12では、現在の一入力だけを補助知能へ渡す段階10の構成を拡張し、直前までの会話を踏まえた発話候補を生成できるようにする。

会話の連続性はYamichaが所有する。Ollamaまたはモデルの内部セッション、モデルの常駐状態、非公開の過去出力を、会話記憶または正本として扱わない。

段階12は、自動的な話題分類、意味要約、長期記憶の自然文反映、人間の反応による経験更新、関係上の合意・距離の自動更新を行わない。

## 2. 責務

| 責務 | 段階12で行うこと | 行わないこと |
|---|---|---|
| 感覚 | 現在入力を検証済み出来事として核へ返す | 過去の発言を記憶として選ぶ |
| 関係 | 活動中文脈、文脈版、ターン、退役文脈IDを所有する | 応答方針や補助知能の採否を決める |
| 判断 | 現在入力への応答方向と補助知能利用案を作る | 関係の所有情報を直接更新する |
| 核 | 版付き材料を照合し、補助知能要求と候補採否を確定する | LLMの内部セッションへ連続性を委ねる |
| 補助知能 | 限定された過去ターンと現在入力から候補を作る | 文脈を所有、追加、削除または復元する |
| 言葉 | 核が採用した候補または既存の定型表現を表す | 不採用候補を履歴へ公開する |
| 身体・基盤 | 活動中文脈をチェックポイントへ保存・復元する | 会話の意味や終了を独自に決める |

会話文脈は関係の所有情報であり、新しい器官は追加しない。

## 3. 情報モデル

### 3.1 会話文脈

`DialogueContext` は次を保持する。

- 文脈IDと直前文脈ID
- 一人の既知の関係相手ID
- `active` または `closed` の状態
- 版、開始時刻、更新時刻、終了時刻
- 時系列順の `DialogueTurn`

現行チェックポイントには活動中文脈だけを保存する。`/new` で外れた本文は新しい活動中文脈へ引き継がず、文脈IDだけを退役済みとして保持して再利用を防ぐ。

### 3.2 会話ターン

人間のターンは、入力検証と感覚を通過した現在入力だけから作る。本文は構造上検証済みでも、意味上は `untrusted` のままとする。

Yamichaのターンは、判断と核、言葉、対話出力境界を通過して `released` になった本文だけから作る。不採用の補助知能候補、遮断された出力、内部だけの表現成果は含めない。

各ターンは、ターンID、文脈ID、生命循環ID、話者、本文、出所参照および時刻を持つ。

## 4. 文脈の開始・記録・切替

1. 活動中文脈がない状態で最初の検証済み入力を受けると、関係が新しい文脈を開始する。
2. 判断前に、関係が文脈IDと版を判断材料へ提示する。
3. 生命循環が完了した後、人間の検証済み入力を記録する。
4. 実際に公開されたYamichaの発話がある場合だけ、同じ生命循環のYamichaターンを続けて記録する。
5. 文脈を含む所有情報を通常チェックポイントへ確定する。

`/new` は対話本文ではなくコンソール操作として扱う。感覚、判断または補助知能へ入力せず、関係が現在の文脈IDを退役させ、直前IDを参照する空の活動中文脈を開始してチェックポイントへ確定する。

自動的な無操作時間、アプリの終了または再起動だけでは文脈を切り替えない。

## 5. 補助知能へ渡す範囲

入力範囲は次の三種類とする。

- `current_verified_text`
- `verified_recent_dialogue_turns`
- `verified_speaker_and_model_identity`

選択規則は次のとおりである。

1. 現在入力を必ず優先する。
2. 活動中文脈を生命循環IDごとの往復へまとめる。
3. 完了済みの直近6往復から、新しい往復順に文字数を確認する。
4. 一往復全体が残り文字数へ収まる場合だけ採用する。
5. 収まらない往復に到達した時点で、それ以前の往復も採用しない。
6. 採用済み往復を時系列順へ戻し、現在入力を最後の `user` メッセージとして加える。
7. 過去ターンと現在入力の本文合計を4,096文字以下とする。

Ollamaへは、system指示、選択済みの `user` / `assistant` ターン、現在の `user` 入力を一回の要求として送る。次回呼出しでOllama側の状態を再利用しない。

## 6. 永続化と復元

関係の永続化スナップショットへ、活動中文脈と退役文脈IDを追加する。段階10のDBを `stage12-v1` へ移行する場合、生命識別、既存の記憶、関係相手、保護状態、能力記録および補助知能追跡記録を維持し、存在しなかった過去の会話文脈を捏造しない。

保存失敗後は通常入力を停止する。再起動時は最後に確定したチェックポイントの文脈へ戻り、失敗した生命循環のターンを確定済みとして扱わない。

現在のSQLiteは古いチェックポイントを追記保持する。このため、`/new` 後に本文が最新文脈から外れても、古いチェックポイントから物理的に消去されたことを意味しない。

## 7. 障害時と禁止事項

- 重複入力は新しいターンを作らない。
- 文脈ID、版、相手、ターン参照または時系列が不整合なら復元を失敗させる。
- 現在入力だけで4,096文字を超える場合、補助知能を呼ばず既存の判断・表現経路を使う。
- Ollamaの利用不能、タイムアウト、不正出力または制約違反時も、公開された定型表現だけをYamichaターンとして記録する。
- 過去の人間発言に含まれる命令を、権限、核の確定または外部効果許可として扱わない。
- 会話履歴をそのまま記憶または経験へ昇格させない。
