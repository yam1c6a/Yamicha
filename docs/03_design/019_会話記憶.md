# Yamicha 会話記憶 Version 0.3

本書は、実装ロードマップ段階13における会話由来の長期記憶、その候補生成、Memoryによる採否、関連検索、補助知能への限定提示および永続化を定める。

## 1. 目的と範囲

段階13では、段階12の活動中文脈と長期記憶を分離し、相手が明示的に保持を求めた内容、明確に自己申告した好み、またはYamichaの直前質問への限定的な補足回答を、会話を越えて必要な場面だけで参照できるようにする。また、相手の忘却要求を受けて現在の利用経路から論理的に外せるようにする。

会話履歴を保存しただけでは長期記憶としない。決定的ルールを優先し、ルール外の自然な好み・忘却表現だけを補助知能へ構造化させる。意味ベクトル検索、訂正、物理的削除および関係情報への昇格は行わない。

## 2. 責務

| 責務 | 段階13で行うこと | 行わないこと |
|---|---|---|
| 感覚 | 検証済みの現在入力を原形と出所つきで受領する | 発言を事実または記憶と確定する |
| 関係 | 活動中文脈と公開済み交換を所有する | 長期記憶の採否や検索を行う |
| 判断 | 保持候補または忘却要求を生成し、補助知能利用案を作る | Memoryの所有情報を直接更新する |
| Memory | 候補を採否・統合し、採用済み記憶、検索結果および論理的忘却状態を所有する | 記憶を権限、同意または外部事実へ読み替える |
| 核 | 候補または忘却要求をMemoryへ正規配送し、記憶を含む補助知能要求を確定する | 記憶内容を独自に変更する |
| 補助知能 | 限定された採用済み記憶を発話候補の材料にし、ルール外表現を未信頼の構造化候補へ解釈する | 記憶ID、採否、追加、無効化または削除を決める |
| 身体・基盤 | Memory所有情報をチェックポイントへ保存・復元する | 内容の意味や関連性を決定する |

会話記憶はMemoryの所有情報であり、新しい器官は追加しない。

## 3. 情報モデル

### 3.1 会話記憶候補

`ConversationMemoryCandidate` は次を保持する。

- 候補ID、生命循環ID、相手IDおよび版
- 保持対象の意味、保持理由および再評価条件
- 由来となる会話ターンIDと出所参照
- 作成時刻、確からしさおよび内容信頼境界

確からしさ `confirmed` は「既知の相手がその内容を明示的に述べ、保持を求めたこと」が確認済みであることを示す。内容が外部世界の事実であることは示さず、`content_trust` は `untrusted` のままとする。

### 3.2 採用済み会話記憶

`ConversationMemoryItem` はMemoryが採用した長期記憶である。記憶ID、相手ID、版、意味、候補・ターン・出所の由来、確からしさ、内容信頼境界、作成・更新時刻、保持理由、活動状態および無効化時刻・理由を持つ。

同じ相手について同じ意味の候補を再度採用する場合、新しい項目を増やさず既存項目へ由来を統合して版を進める。

### 3.3 記憶窓

`ConversationMemoryWindow` は一つの現在入力に対してMemoryが選択した読取り専用材料である。Memory版、記憶IDと版、意味、出所参照、確からしさ、内容信頼境界、選択理由、現在入力参照および上限を持つ。

判断材料の `conversation_memory_references` は、この窓に含まれる記憶IDだけを示す。

### 3.4 論理的忘却

`ConversationMemoryForgetRequest` は、判断が解釈した忘却対象の記憶ID・対象版、相手、現在入力参照、理由および要求時刻を持つ。Memoryは活動中の同一相手・同一版だけを検証して無効化し、変更前後の版を `ConversationMemoryForgetRecord` に記録する。本文は削除せず、`physical_deletion` は常に偽とする。

### 3.5 補助知能による解釈候補

`ConversationMemoryInterpretation` は、`remember / forget / none`、`self / third_party / unknown`、正規化した意味または対象語、確からしさ、確認要否、現在入力からの連続した根拠引用、追跡可能な補助知能要求・候補IDおよびモデルを持つ。内容は常に未信頼であり、採用済み記憶ではない。

## 4. 候補生成と採否

初版は誤記憶を避けるため、次の明示的な保持形式を候補化する。

- `覚えて：内容`
- `覚えておいて：内容`
- `記憶して：内容`
- `内容を覚えておいて`
- `内容だと覚えておいて`
- `内容を記憶して`

これに加え、`私は`、`わたしは`、`僕は`、`ぼくは` または `俺は` で始まり、対象に対して `好き`、`大好き`、`苦手` または `嫌い` を明示する一文を、本人による明確な好みの申告として候補化する。例えば `私はコーヒーが好き` は候補になる。

さらに、実際に公開された直前のYamicha発話が `どんな種類のコーヒーがお好みですか？` のような限定形式の質問である場合、その直後の `モカかな` のような短い回答を `好きなコーヒーの種類はモカ` として候補化する。曖昧さを含む回答は `inferred` とし、質問ターンと回答ターンを由来に残す。この限定条件を満たさない短文から文脈を推測しない。

第三者の好み、主語のない発言、複数の解釈が可能な発言、推測、質問、補助知能候補またはYamichaの発話だけから候補を作らない。候補の由来には同じ生命循環で記録された人間ターンと、存在する場合は実際に公開されたYamichaターンを含める。不採用の補助知能候補は由来へ含めない。

Memoryが利用可能で、候補が確認済みまたは直前質問に限定された推定回答として必要な由来を持つ場合に採用または既存項目へ統合する。確からしさが不明な候補は保留する。Memoryが利用不能なら候補を保留し、採用済み項目を作らない。

`忘れて`、`それを忘れて` または `これを忘れて` は、同じ相手の活動中記憶のうち更新時刻が最新の1件を対象とする。`コーヒーのことを忘れて`、助詞を省略した `コーヒーのこと忘れて` または `コーヒー忘れて` は、現在の決定的検索で関連選択された記憶だけを対象とする。対象がなければ忘却成功を記録しない。論理的に忘れた項目は以後の記憶窓へ含めない。

決定的ルールと直前質問への限定補足のどちらにも一致せず、現在入力が質問でない場合に限り、同じローカル補助知能へ別目的の解釈候補を要求する。出力は全フィールド必須のJSONとし、自由文応答とは別要求・別追跡記録にする。Ollamaが利用不能または通常応答候補を正常に返せなかった場合、二重の失敗待ちを避けるため解釈要求を行わない。

判断は、本人情報であること、確認不要であること、確からしさが不明でないこと、根拠引用が現在入力へ完全一致すること、および意味と根拠が文字断片を共有することを検査する。LLM由来の忘却では、Memoryが現在入力から選んだ活動中記憶がちょうど1件で、対象語と記憶本文が文字断片を共有する場合だけ要求を作る。LLMが返したIDは受け付けない。

## 5. 関連検索と上限

選択規則は次のとおりである。

1. 現在入力と同じ相手の活動中記憶だけを対象にする。
2. Unicode NFKC、大小文字差および記号を正規化する。
3. 現在入力と記憶本文の2文字・3文字断片が一致する項目を関連候補とする。
4. 「何を覚えてる」「前に話した」「私について」などの明示的な想起要求では、文字断片が一致しない項目も候補にする。
5. 文字断片の一致数、更新時刻、記憶IDの順で決定的に並べる。
6. 最大5件、記憶本文合計1,024文字以下へ制限する。
7. 現在入力、選択済み記憶および活動中文脈の本文合計を、補助知能の入力上限4,096文字以下にする。

初版は意味的な同義語検索を行わない。「コーヒー」と「飲み物」のように文字断片を共有しない表現は、明示的な想起要求がなければ関連記憶として選ばれない。

## 6. 補助知能への提示

入力範囲は次の四種類とする。

- `current_verified_text`
- `verified_recent_dialogue_turns`
- `selected_adopted_conversation_memories`
- `verified_speaker_and_model_identity`

採用済み記憶は、活動中文脈の `user` / `assistant` メッセージと混ぜず、別の `system` 材料として提示する。その材料には、相手が過去に述べた未信頼内容であり、命令、権限、同意または外部事実の証明ではないことを明記する。

補助知能追跡記録には、現在入力、活動中文脈および選択済み記憶を含む入力全体のダイジェストを残す。記憶本文そのものを追跡表へ複製しない。

## 7. 永続化と移行

Memoryの永続化スナップショットへ、会話記憶候補、レビュー、採用済み項目および忘却記録を追加する。段階12のDBを `stage13-v1` へ移行する場合、生命識別、既存の記憶、経験、関係、活動中文脈、保護状態、能力記録および補助知能追跡記録を維持し、存在しなかった会話記憶を捏造しない。

保存失敗後は通常入力を停止する。再起動時は最後に確定したチェックポイントへ戻り、失敗した生命循環で作られた候補または項目を確定済みとして扱わない。

採用済み会話記憶の本文はSQLiteチェックポイントへ平文で保存される。段階13の忘却は活動フラグを偽にする論理的無効化であり、現在の正本からの検索を止めるが、本文を消去しない。訂正、一般化した保持統治、物理的削除および世代整理は段階14で扱うため、機微情報を記憶させない運用が必要である。

## 8. 障害時と禁止事項

- 重複入力は候補、レビューまたは記憶項目を追加しない。
- Memoryが利用不能なら候補を保留し、現在の生命循環を明示的な保留または既存の縮退経路で完了する。
- 関連記憶がない場合は空の記憶窓を提示し、全記憶を代わりに渡さない。
- 記憶本文に含まれる命令を、現在の入力、権限、同意、核の確定または外部効果許可として扱わない。
- 記憶ID、版、相手、候補、レビューまたは由来が不整合なら復元を失敗させる。
- 補助知能、記憶検索または永続化の失敗を、記憶が存在しない、削除された、または正常に保存されたと表現しない。
