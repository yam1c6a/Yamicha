# Yamicha 永続化と復元 Version 0.1

本書は、実装ロードマップ段階7における永続化、正常停止・異常終了の識別、および同一生命としての復元境界を記録する。

## 1. 基本方針

SQLiteは記憶そのものでも情報の論理所有者でもない。状態、核、記憶、関係および保護境界が、それぞれ自分の所有情報を版付きスナップショットとして提示し、身体・基盤側の永続化機構が物理I/Oだけを担当する。

```text
各所有者の確定済み情報
  → 段階7スナップショット調整
  → SQLiteの一つのトランザクション
  → チェックサム付き確定チェックポイント
  → 再起動時に各所有者が自分の領域へ復元
```

保存アダプタは保存内容の意味、候補の採否、判断方向または関係状態を決めない。

## 2. 永続化する情報

| 情報 | 論理所有者 | 保存内容 |
|---|---|---|
| 生命識別・構成版 | 構成境界 | 主体ID、構成版、永続化スキーマ版 |
| 状態 | State | 稼働状態、内部時刻、最終相関ID、材料版 |
| 生命循環記録 | Core | 出来事・判断・表現・結果の記録と正本参照 |
| 記憶・経験候補 | Memory | 候補、候補版、評価結果 |
| 採用済み記憶 | Memory | 意味、確からしさ、由来、更新理由、版 |
| 関係 | Relationship | 既知の相手識別と版 |
| 保護状態 | Protection boundary | 通常対話出力の許可状態と版 |

記録、候補、採用済み記憶は別の意味型のまま保存する。SQLiteのJSONペイロードへまとめることは、これらを同じ意味として扱うことを意味しない。

## 3. 確定単位

入力なしの生命循環が完了した時点、および受理済み入力について言葉と出力境界まで完了し、段階6の記録作成・候補評価が終わった時点で、それぞれ一つのチェックポイントを作る。状態、全記録、Memory所有情報、関係、保護状態および構成版は、SQLiteの一つのトランザクションでまとめて確定する。

書込みが途中で失敗した場合、そのトランザクションは確定されない。プロセス内では処理済みに見える情報があっても、再起動時には直前の確定チェックポイントだけを採用する。これにより中断された入力が確定済み記憶へ混入しない。

ここでいう「最終正常状態」は、正常停止時だけに作られる状態ではなく、整合性検査を通ってトランザクションが完了した最新のチェックポイントを指す。

## 4. 正常停止と異常終了

起動ごとにセッションIDを発行し、開始時は `running` として記録する。`/quit`、入力終了、または明示的な停止で終了処理が完了した場合だけ `normal` へ更新する。

次回起動時、直前セッションが `running` のままなら異常終了として報告する。異常終了でも確定済みチェックポイントの完全性が確認できれば、それを同一生命として復元できる。未確定の書込みは復元対象にしない。

## 5. 復元と継続不能条件

チェックポイントには連番、主体ID、構成版およびSHA-256チェックサムを持たせる。復元時はSQLiteの整合性検査に加えて、次を検証する。

- 保存スキーマ版と現在の対応版が一致する
- 主体IDと構成版が索引・ペイロード・生命識別で一致する
- チェックポイント連番とスナップショットIDが一致する
- 各意味型の必須値、版およびID一意性が成立する
- Memoryが復元する候補と記憶がMemory所有の整合条件を満たす

DB破損、チェックサム不一致、構成版不一致、生命識別欠落、確定済みチェックポイント欠落、および所有者が受理できない内容は、継続不能の例外として起動を中止する。復元に失敗した内容を空の新規生命として黙って開始しない。

新しいDBにチェックポイントがない場合は「初期化」と明示し、「復元」とは扱わない。既存DBを必須とする起動経路では、DBファイル欠落も明示的な失敗にできる。

## 6. 保存場所と操作

対話コンソールの既定保存先はリポジトリ直下の `.yamicha/yamicha.sqlite3` である。このディレクトリはGit管理対象外とする。保存先は次のように変更できる。

```shell
python scripts/chat.py --db path/to/yamicha.sqlite3
```

Python標準ライブラリの `sqlite3` だけを使用し、外部DBサービスや追加依存関係は使用しない。

## 7. 現在の制限

- 通常チェックポイントから独立した保護状態・監査および能力重複防止記録は段階8・9で追加済み
- 能力を介して永続化製品そのものを交換する契約は未実装
- バックアップ、世代管理、スキーマ移行および忘却処理は未実装
- 複数プロセスから同じ生命DBを同時起動する運用は対象外
- 永続化した記憶を自然な会話文へ反映する機能は未実装
