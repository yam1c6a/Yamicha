# Yamicha 最小判断 Version 0.1

本書は、実装ロードマップ段階4における判断材料、候補生成、核の最終確定および差し戻しの実装境界を記録する。

## 1. 判断経路

```text
検証済み文字事象
  → 核が状態・記憶・関係への参照要求を完了
  → 状態・記憶・関係・保護境界が版付き判断材料を提示
  → 判断が6方向すべての候補と採否理由を記録
  → 判断が1方向を提案
  → 核が生命循環、材料版、境界、現在条件との整合だけを確認
  → 同じ方向を最終確定、または方向を変えずに差し戻し
```

段階4では、言葉による応答、能力実行、外部効果、記憶更新および関係更新を行わない。

## 2. 判断材料の所有者

| 所有者 | 提示する材料 |
|---|---|
| 状態 | 稼働状態、制約、材料版 |
| 記憶 | 関連参照、既知の不確実性、材料版 |
| 関係 | 相手の既知性、同意、境界違反と理由、材料版 |
| 保護境界 | 入力検証、意味上の非信頼、外部効果不許可、材料版 |

核は各所有者の正本を代行せず、一つの `JudgmentContext` に結び付ける。判断結果は使用した材料版を保持し、最終確定時に版が変わっていれば差し戻す。

## 3. 候補と最小選択規則

判断は常に次の6方向を一度ずつ候補として記録する。

- `RESPOND`: 応答する
- `CONFIRM`: 確認する
- `HOLD`: 保留する
- `REFUSE`: 拒否する
- `WAIT`: 待機する
- `NO_ACTION`: 無操作とする

各候補は、選択時の採用理由または不採用時の不採用理由を持つ。重要材料不足は不確実性として明示し、推測で補わない。

現在の最小規則は、優先順に次のとおりとする。

1. 状態・記憶・関係・相手・入力検証の重要材料が不足していれば `HOLD`
2. 関係が境界違反を提示していれば `REFUSE`
3. 明示的な待機要求なら `WAIT`
4. 明示的な無操作要求なら `NO_ACTION`
5. 外部効果を伴う可能性があれば、対象・権限・効果の確認条件を付けて `CONFIRM`
6. それ以外で材料が整合していれば `RESPOND`

規則は外部知能を呼び出さず、入力本文を命令として実行しない。

## 4. 判断と核の分離

判断は候補を生成して1方向を提案する。核は新しい候補を作らず、提案方向も変更しない。

核は次だけを確認する。

- 生命循環IDが一致する
- 判断時と最終確定時の材料版が一致する
- 状態が入力判断可能な待機状態である
- 入力が保護境界で検証済みかつ意味上は非信頼のままである
- 保護境界が外部効果を許可していない
- 重要材料不足時の提案が `HOLD` である
- 境界違反時の提案が `REFUSE` である

不整合時は `REMANDED` とし、最終方向を空にする。核が別方向へ置き換えることは禁止する。
