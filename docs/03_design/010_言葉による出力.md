# Yamicha 言葉による出力 Version 0.1

本書は、実装ロードマップ段階5における表現要求、言葉、核の表現確認、対話出力境界および沈黙の実装境界を記録する。

## 1. 出力経路

```text
判断が選んだ方向
  → 核が同じ方向を最終確定
  → 核が方向と根拠に対応する分類済みの意味項目を作成
  → 言葉が意味項目を定型文へ変換し、表現成果を核へ返す
  → 核が方向・意味項目・実行状態との一致だけを確認
  → 保護境界が通常対話の出力を解放、沈黙、または遮断
  → コンソール等の対話チャネルが解放済み文字列だけを表示
```

言葉は未信頼の入力本文を直接参照しない。入力本文、外部知能の文面または能力結果が、そのままYamichaの確定表現になる経路は設けない。

## 2. 確定方向と表現方法

| 確定方向 | 表現方法 | 外への現れ方 |
|---|---|---|
| `RESPOND` | `RESPONSE` | 受領した事実を短く応答する |
| `CONFIRM` | `CONFIRMATION_REQUEST` | 推論、未確認、未実行、確認要求を分けて表す |
| `HOLD` | `HOLD_NOTICE` | 情報不足と保留を分けて表す |
| `REFUSE` | `REFUSAL_NOTICE` | 境界違反と拒否を分けて表す |
| `WAIT` | `SILENCE` | 内部判断を保持して文字を出さない |
| `NO_ACTION` | `SILENCE` | 内部判断を保持して文字を出さない |

この対応は契約で固定する。言葉は確定方向を別の方向へ変更せず、話すか沈黙するかも単独で決めない。

## 3. 意味と表現の分離

核が作る `ExpressionItem` は、意味、分類、根拠参照だけを持つ。分類は次を区別する。

- `FACT`: 検証済みの受領や未実行状態
- `INFERENCE`: 外部効果が必要である可能性
- `UNKNOWN`: 対象、権限、効果または判断材料の不足
- `CONFIRMATION_REQUEST`: 相手へ確認する必要
- `REFUSAL`: 境界を守るための拒否
- `HOLD`: 材料不足による保留

言葉は、これらを日本語の定型文へ変換する。段階5では自然で豊かな文章生成や外部知能を使用しない。

## 4. 核による表現確認

言葉が返した `ExpressionArtifact` に対し、核は次を機械的に確認する。

- 生命循環ID、表現要求IDおよび確定方向が一致する
- 表現方法が確定方向に対応する
- 意味項目が追加、削除または変更されていない
- 確認されていない外部効果を完了済みと主張していない
- 外部知能を使用していない

不一致時は `REEXPRESSION_REQUIRED` とし、核は表現を修正せず再表現を求める。段階5の通常経路では、すべての外部効果が未実行である。

## 5. 出力境界と沈黙

保護境界は、核が受理した同一の表現成果だけを通常対話へ解放する。

| 状態 | 意味 |
|---|---|
| `RELEASED` | 直接対話の出力境界を通過し、対話チャネルが表示可能 |
| `SILENT` | 確定された沈黙を保持し、文字列を出さない |
| `BLOCKED` | 核の受理不一致または保護状態により文字列を出さない |

`RELEASED` はメール送信、公開、削除、更新その他の外部操作完了を意味しない。それらは言葉ではなく能力と外部効果ゲートを必要とし、段階5の対象外である。

沈黙時も、生命循環ID、判断結果、確定方向、表現要求、沈黙表現成果および出力境界結果を `Stage5InputOutcome` から追跡できる。
