# 経験の対話反映

## 1. 目的

本書は、実装ロードマップ段階16における経験証拠の受領、確認、採用、限定利用、見直しおよび復元を定める。

実際に公開した応答に対する相手の明示的な反応を、別入力による確認後に限定された判断・表現方針へ反映する。単なる後続発言、沈黙、親しげな発言または補助知能の評価から、成功、失敗、好意や不満を確定しない。

## 2. 責務

| 責務 | 段階16で行うこと |
|---|---|
| 判断 | 明示的な反応、確認、取消、見直しおよび不採用を要求へ変換し、採用済み経験の限定された方針を判断する |
| 核 | 現在の入力と確定済み判断に対応する要求だけを認め、経験が既存の境界や権限を変更しないようにする |
| Memory | 証拠、経験の正本、確認待ち、変更前後、理由、適用範囲、再評価条件および利用履歴を所有する |
| 関係 | 実際に公開した応答と会話文脈を所有し、経験の対象となった生命循環を追跡する |
| 言葉・補助知能 | 現在有効な方針の範囲で表現候補を生成し、採否と出力境界を経て応答する |
| 永続化 | 証拠、経験版、確認待ち、変更履歴および利用履歴を同じチェックポイントへ保存する |
| 表示境界 | 経験の一覧と管理結果に対して、保護状態と通常出力の権限を確認する |

経験は、会話記憶や関係情報とは別の意味型としてMemoryが所有する。補助知能は経験の採用、正本の変更または能力の許可を決めない。

## 3. 証拠と確認

経験の対象は、実際に公開した対話の生命循環または登録された能力実行結果とする。入力元、対象、由来、検証状態および確認入力を保持する。対象となる応答が存在しない場合や、別の相手の反応は採用しない。

「直前」は管理操作を除いた最後の公開応答と照合する。その応答が拒否・保留など経験の採用対象外の場合や、対応する根拠を確認できない場合は候補を拒否し、以前の通常応答に反応を結び付けない。対話を根拠とする見直しにも同じ照合を行う。

人間の「成功した」という発言と、能力から返された実行結果は別の証拠とする。人間の申告を能力実行の成功証明へ読み替えず、結果不明を成功として扱わない。

通常の「ありがとう」や「長すぎた」という発言だけでは方針を変更しない。明示的な経験操作を受けても、別入力による確認までは経験を利用しない。補助知能による自己評価、推測または生成文は確認の代わりにならない。

## 4. 対話操作

通常の対話で応答を受け取った後、次の入力を使う。

| 入力 | 結果 |
|---|---|
| `経験：直前：長すぎた` | 直前の応答を根拠とし、短い表現への変更を確認待ちにする |
| `経験：直前：説明が足りなかった` | 説明量を増やす方針への変更を確認待ちにする |
| `経験：直前：確認してから答えてほしかった` | 回答前に確認する判断方針への変更を確認待ちにする |
| `経験：直前：確認せず答えてほしかった` | 通常の判断に従って応答する方針への変更を確認待ちにする |
| `経験：能力:結果ID：反応` | 登録済みの能力実行結果に対する反応を確認待ちにする |
| `経験確認` | 現在の相手に属する確認待ちを確定する |
| `経験取消` | 確認待ちを取り消す |
| `経験見直し：ID：反応` | 新たな証拠を根拠に、指定した経験の見直しを確認待ちにする |
| `経験不採用：ID` | 指定した経験を通常利用から外す変更を確認待ちにする |
| `/experience` | 採用中の経験のIDと方針を表示する |
| `/experience all` | 不採用を含む経験を表示する |

`はい` や `関係確認` は経験の確認として扱わず、`経験確認` は記憶の物理削除や関係情報の確認として扱わない。

確認待ちは相手ごとに一件で、既定の確認期限は24時間とする。確認には変更を申し出たときと同じ会話文脈が必要である。取消は同じ相手であれば新しい会話からも行える。採用済み経験に自動失効の期限は設けず、見直しまたは不採用で状態と版を更新する。

既定の適用範囲は同じ相手・同じ会話文脈・対話判断に限る。末尾に ` | 話題=コーヒー` を付けた場合は、同じ相手が指定した語句を含む入力をしたときに、会話文脈を越えて利用できる。対象外の相手、能力または判断種別へ一般化しない。

## 5. 判断と表現への反映

経験の変更対象と変更後の値は有限とする。表現量は短い応答または詳しい応答、判断方針は回答前の確認など、実装が検査できる範囲だけを扱う。自由文を実行規則として解釈しない。

短い応答では出力文字数を最大160文字、詳しい応答では構成された上限（既定800文字）までとし、構成上限を越えて増やさない。回答前の確認は判断方向へ反映する。補助知能へ説明文を追加するだけで経験を適用したことにはしない。経験によって保護、権限確認、外部効果の確認や停止・保留の判断を弱めない。

経験による確認を実際に公開した場合、同じ会話・同じ経験版に対する次の入力は確認への回答として通常応答へ進む。公開した確認と経験版の記録を照合し、補助知能にも回答を生成する段階であることを渡す。この扱いは一回限りで、次の新しい質問には再び確認を行う。再起動後も対応するが、新しい会話・経験版の変更・管理入力などの割込み・非公開の確認からは引き継がない。外部操作に必要な確認や拒否・保留・待機の判断は維持する。

能力実行結果からの経験は、同じ会話内で同じ対象を明示した対話への反映に限る。読み取り自体の実行条件、能力操作の選択や外部効果の権限は変更しない。現在の能力は読み取り専用であり、経験操作はPython APIで登録した実結果のIDを参照する。

経験は変更対象ごとに一件、合計最大2件・方針本文256文字まで選ぶ。利用した経験のIDと版を生命循環に対応付けて記録する。経験の管理入力と応答は、通常の会話履歴として補助知能へ再投入しない。今回選ばれていない経験、不採用の経験または古い版に依存した過去の応答も、補助知能用の文脈から除外する。

## 6. 見直しと復元

見直しでは変更前後、理由、新たな証拠、対象版および再評価条件を記録する。確認前は従来の版を維持し、確認後は新しい版だけを選択する。対象版が変わった確認待ちや、期限を過ぎた確認は採用しない。不採用は通常利用からの除外であり、証拠や履歴の物理削除ではない。

話題を指定した経験は、新しい会話でその経験の現在版を実際に利用した公開応答があれば、同じIDの新版として見直せる。証拠と利用履歴の相手・会話・時刻・経験版を照合し、元の会話の識別子と適用話題を維持する。対象外の話題の応答、利用版の不一致、能力由来の経験や適用範囲の拡張を根拠に、会話を越えた見直しは行わない。

構成版は `stage16-v1` とする。段階13・14・15のDBから、生命識別、記憶、関係情報、会話文脈および保護状態を保って直接移行する。旧データから経験を推測で作らず、未対応の構成版は拒否する。

再起動後も経験、証拠、確認待ち、変更履歴および利用履歴を復元する。保存失敗時は後続の変更を停止し、次回起動時に最後の確定済みチェックポイントを復元する。LLMの停止や交換によって経験の正本は失われない。

## 7. 品質確認と制約

`tests/test_stage16_experience_dialogue.py` では、未確認反応の非採用、別入力による確認、適用範囲、実際の判断と文字数制約、見直し後の旧版排除、管理確認の分離、保存失敗と再起動、旧構成からの移行および保護中の表示拒否を検証する。

品質確認コマンドは `python scripts/quality.py` とする。対話試験には決定的なテスト用応答を用いる。自然な表現の品質、自由な感情推定、任意の行動方針の自動生成および能力の自動選択は本段階の対象外である。

2026-10-27に全256件のテスト、コンパイル、依存方向およびUTF-8検査の成功を確認した。独立レビューで見つかった能力結果の保存障害後の継続と、記憶削除確認の経験証拠への混入は、修正と回帰試験を追加した。Ollama送信内容・入力範囲・追跡ダイジェストは `test_stage16_intelligence_boundary.py`、能力保存障害は `test_stage16_capability_recovery.py` でも検証する。

追加レビューの確認ループ、直前応答の根拠取り違え、別会話での見直し不可を修正し、`test_stage16_confirmation_followup.py`、`test_stage16_latest_evidence.py`、`test_stage16_topic_reassessment.py` に回帰試験を追加した。独立した再確認では、話題別の確認方針を別会話へ適用し、再起動後の回答、同じIDの見直し、再度の復元および拒否後の根拠除外を組み合わせた経路にも成功した。

既存DBと分離した一時DBで `gemma4:e4b-it-qat` を用い、実応答への反応と別入力確認、160文字上限の適用、再起動後の同じ経験版の利用を確認した。採用された実応答は確認後60文字、再起動後59文字であった。

確認ループの修正後も同じモデルと一時DBで検証した。経験由来の確認を公開した後に再起動し、相手が対象と知りたい点を答えると55文字の実応答が採用された。さらに次の新しい質問では再び確認を行い、一回限りの復帰であることを確認した。
