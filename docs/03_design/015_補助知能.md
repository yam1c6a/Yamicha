# Yamicha 補助知能 Version 0.1

本書は、実装ロードマップ段階10におけるローカル外部AI接続、目的と入力範囲の限定、候補材料の採否、障害時の継続および追跡記録を定める。

## 1. 外部知能の位置づけ

段階10では、Ollamaで動作する `gemma4:e4b-it-qat` を補助知能器官から利用する。同じ端末内で動作していても、モデルとOllamaはYamichaの外部領域であり、主体、判断または核ではない。

外部知能が返した文章は未検証の候補である。外部知能自身は、候補の採否、Yamichaの最終方向、外部操作、記憶更新、経験の意味、保護作動または解除を決定できない。

## 2. 固定した目的と入力範囲

段階10の使用目的は `dialogue_response_candidate` 一種類だけである。会話内容の入力範囲は、保護境界と感覚を通過した現在の文字入力 `current_verified_text` だけに限定する。これに加え、構成時に確認済みの話者名 `Yamicha` と補助モデル名だけを `verified_speaker_and_model_identity` として渡す。

次の情報は既定で外部知能へ渡さない。

- SQLiteの内容
- 過去の入力本文と応答本文
- 記憶、経験候補および関係の正本
- 保護監査と能力実行履歴
- ファイル、環境変数、認証情報およびシステム情報
- 読み取り能力が取得した外部内容

確認済みの話者情報は、補助知能自身を画面上の話者にしないために使う。補助知能はYamichaの発話候補だけを作り、自分を補助知能、AI、言語モデルまたはGemmaとして名乗らない。補助モデルを尋ねられた場合は、Yamichaが確認済みモデルを補助に使っているという関係で答える。

入力は最大4096文字、出力候補は最大800文字、待機時間は最大60秒とする。出力形式は `reply` 文字列一つを持つJSONに固定する。

## 3. 処理経路

```text
検証済み文字入力
  → Sensationが出来事として受領
  → Judgmentが通常の方向を提案
  → CoreがRESPOND方向を最終確定
  → Judgmentが限定目的の補助知能利用案を発行
  → Coreが同じ案を統合要求として許可
  → AuxiliaryIntelligenceがOllamaへ要求
  → 未検証候補または明示的な失敗結果を受領
  → Judgmentが候補材料としての構造的利用可否を確認
  → Coreが同一ライフサイクルへの採用または不採用を確定
  → Languageが採用候補を表現成果へ変換
  → Coreが採用内容との完全一致を検査
  → ProtectionBoundaryが許可された文章だけを解放
```

補助知能利用は、通常判断で `RESPOND` が確定した場合だけ行う。確認、拒否、保留、待機または無操作の方向を、モデル出力によって応答へ変更しない。

## 4. 候補の検査と採否

補助知能器官は、Coreが実際に発行した統合要求だけを受ける。モデル名、完了状態、JSON形式、必須フィールド、空文字、出力長、制御文字および未確認の外部効果を完了したとの表現を検査する。

合格した文章にも `unverified` を付け、出所を `ollama-local:<model>` として保持する。Judgmentの確認は候補材料として利用可能かの提案であり、採用の最終確定ではない。

Coreは、補助知能自身を話者として名乗る候補を拒否する。相手が話者の名前・正体を尋ねた場合は `Yamicha` を含むこと、補助モデルを尋ねた場合は構成済みの正確なモデル名を含むことを確認する。これは自然言語全般の理解ではなく、自己同一性を守るための固定検査である。

Coreは、実際に発行された要求、補助知能器官が実際に発行した結果、Judgmentが実際に発行した確認、および通常判断の確定方向が同じライフサイクルを指す場合だけ候補を採用する。

LanguageはCoreが採用した候補を変更せず表現成果へ移す。Coreは成果の本文、意味項目、方向、要求、候補および外部効果主張を再検査する。採用証拠の偽造、本文変更または未確認効果の付加があれば、出力境界は文章を解放しない。

## 5. 障害とフォールバック

次を区別して結果として保持する。

| 状態 | 意味 | 対応 |
|---|---|---|
| `unavailable` | Ollamaへ接続できない | 定型応答へ戻る |
| `timeout` | 制限時間内に完了しない | 定型応答へ戻る |
| `invalid_output` | 通信形式または候補JSONが不正 | 定型応答へ戻る |
| `constraint_violation` | 長さ、制御文字または未確認効果主張に違反 | 定型応答へ戻る |

これらは通常判断や生命循環全体の失敗として扱わない。既存の決定、言葉、出力境界、記録、記憶候補評価および永続化を継続する。利用不能なモデルを利用できるように装わない。

## 6. ローカル接続

接続先は `http://127.0.0.1:11434/api/chat` を既定とし、アダプターは `localhost`、`127.0.0.1` または `::1` のHTTP `/api/chat` だけを許可する。外部ホストへの変更は段階10の構成では認めない。

Python標準ライブラリだけを使い、Ollama CLIのPATHには依存しない。非ストリーミング、思考出力無効、JSON Schema指定で呼び出す。

## 7. 追跡と永続化

入力、出力、目的、制約および採否を次の識別情報で結び付ける。

- ライフサイクルID、利用案ID、統合要求ID
- モデル名と利用目的
- 許可された入力範囲
- 入力内容のSHA-256
- 制約全体のSHA-256
- 結果区分
- 出力候補のSHA-256
- Coreの採用または不採用
- 結果と採否の理由および時刻

入力本文と出力本文は補助知能追跡表へ保存しない。追跡行には全項目のハッシュを持たせ、起動時に直接改変を検出する。

段階9の `stage9-v1` DBは、主体ID、チェックポイント、記憶、関係、保護状態、保護監査および能力重複防止記録を維持したまま `stage10-v1` へ移行する。

## 8. 現在の制限

- 複数ターンの会話本文を文脈として渡す処理は未実装
- 復元済み記憶や関係材料を自然な応答へ反映する処理は未実装
- 読み取り能力の結果を補助知能候補へ含める処理は未実装
- モデル選択、状態、追跡履歴および採否を表示するUIは未実装
- モデル出力の事実性を外部資料で検証する処理は未実装
- 外部ホスト上のAI、ストリーミング応答、画像入力およびツール呼出しは対象外
