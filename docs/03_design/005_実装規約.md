# Yamicha 実装規約 Version 0.1

本書は、実装ロードマップの段階0で用いるコーディング規約および依存方向規約を定める。

## 1. 基本規約

- 実装とテストは Python 3.11 以上で動作させる。
- 文字コードは UTF-8、改行は LF とする。
- 公開関数と公開クラスには型注釈を付ける。
- 一つのモジュールに異なる論理責務の所有情報を混在させない。
- 技術上の都合を理由に、九器官、身体・基盤、保護境界または外部効果ゲートの責任を移さない。
- 外部入力、外部知能結果および能力結果を、検証なしで内部情報として扱わない。

## 2. パッケージ境界

| 領域 | 配置 | 許可する内部依存 |
|---|---|---|
| 共通契約 | `yamicha.contracts` | 共通契約 |
| 九器官 | `yamicha.life` | 共通契約、九器官 |
| 身体・基盤 | `yamicha.body` | 共通契約、身体・基盤 |
| 外部接続 | `yamicha.adapters` | 共通契約、外部接続 |
| 合成ルート | `yamicha.bootstrap` | 全領域 |

九器官、身体・基盤および外部接続は相互に直接依存しない。必要な情報交換は共通契約を介し、具体実装の接続は合成ルートで行う。

依存方向は `scripts/check_architecture.py` で検査する。検査規則を緩和する場合は、先に設計判断記録を追加し、上位文書との整合を確認する。

## 3. テスト規約

- 修正した責務の正常系と、少なくとも一つの拒否または失敗系を確認する。
- 依存方向検査そのものが違反を検出できることをテストする。
- 日本語の文書名と内容を含む対象ファイルが UTF-8 として読めることを自動検査する。
- 段階の品質ゲートは、成果物の存在だけでなく実行結果で判定する。

## 4. ログ規約

- 技術ログは一行一JSONオブジェクトとする。
- 生命循環に属するログには空でない `correlation_id` を付ける。
- ログは観測事実を記録し、判断、記憶または主体の所有情報を代行しない。
- 機密情報や外部入力の全量を既定で記録しない。
