# Yamicha 時間と実行機会 Version 0.1

本書は、実装ロードマップ段階2における時間、実行機会、入力のない生命循環および無操作の実装境界を記録する。

## 1. 時間の区別

| 概念 | 型 | 所有・生成 | 用途 |
|---|---|---|---|
| 外部時刻 | `ExternalTime` | 身体・基盤側が観測 | 現実の日時との対応 |
| 単調増加時刻 | `MonotonicTime` | 身体・基盤側が観測 | 巻き戻らない経過計測 |
| 経過時間 | `ElapsedTime` | 基盤が単調増加時刻の差から算出 | 前回機会からの経過 |
| 内部時間 | `InternalTime` | 状態が所有・更新 | Yamichaの内側で経過した時間 |

外部時刻と単調増加時刻の進み方が許容差を超えて食い違う場合、`ClockDiscontinuityError` として停止する。時刻源の巻き戻りや飛びを通常の経過として黙って内部時間へ反映しない。

## 2. 入力のない生命循環

```text
基盤が起動または周期的な実行機会を発行
  → 感覚が内部事象として受領
  → 状態が経過時間を内部時間へ反映し、現在状態を提示
  → 判断が状態を根拠に無操作を提案
  → 核が同じ提案を整合確認して確定
  → 状態と基盤が待機へ移行
```

この段階では、記憶、関係、能力、言葉および補助知能の具体的処理を開始しない。外部効果と記憶更新は発生しない。

## 3. 実行機会と判断理由の分離

`ExecutionOpportunity` は、識別子、連番、種類、時刻および経過時間だけを持つ。欲求、動機または判断理由の項目を持たない。

実行機会は状態確認を行える時機を与えるだけである。判断の根拠は状態が提示する `StateSnapshot` とし、実行機会の到来自体を行動理由にしない。

## 4. 無操作

段階2では、保留事項と制約がない状態スナップショットに対し、判断が `NO_ACTION` を正常な選択案として返す。核は方向を変更せず確定し、循環結果を `COMPLETED` とする。

無操作は失敗、空の結果または実装漏れではない。理由、根拠、相関IDおよび確定結果を追跡でき、外部効果数と記憶更新数がゼロであることを確認する。

## 5. 段階2の制限

- 外部入力の受領と意味処理は段階3以降とする。
- 保留事項、制約または異常が存在する場合の判断は後続段階とする。
- 永続化、復元、外部能力および外部知能は実装しない。
- 技術的停止を、休息、睡眠またはYamicha自身の欲求として扱わない。
