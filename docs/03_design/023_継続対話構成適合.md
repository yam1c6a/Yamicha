# 継続対話構成適合

## 1. 判定対象

実装ロードマップの段階17・品質ゲートG17を対象とする。`make_stage16_system` が生成する一つの構成で、会話文脈、会話記憶、記憶統治、関係情報および確認済み経験を同時に扱う。段階11と同様、適合判定のための新しい器官や `Stage17System` は追加しない。

実行構成版は `stage16-v1`、コンソールの表示は段階16を維持する。パッケージ版は0.7.0とする。段階13・14・15からの既存の直接移行経路と、段階16のDBの復元を維持する。通常の起動は `python scripts/chat.py`、品質確認は `python scripts/quality.py` を用いる。

## 2. 統合検証で解消した不足

### 記憶の利用証跡

以前は選択した会話記憶のIDが一時的な判断材料にあるだけで、再起動後に利用した版を追跡できなかった。核の生命循環記録へ `conversation-memory:ID:v版` を追加し、相手から得た情報であること、確からしさ、本文を含まない選択方式を記録する。由来の入力・候補、相手、変更理由はMemoryの正本と変更履歴に対応付ける。

選択理由に含まれる検索語句や本文断片を、削除対象外の生命循環記録へ保存しない。これらの証跡は情報を利用した事実を表し、その情報が客観的事実であることを証明しない。

### 履歴経由の再混入

忘却後に記憶一覧から消えても、その記憶を使った応答が会話履歴として補助知能へ渡されていた。記憶の元発言と直接利用を追跡し、現在選ばれていない記憶、非活性の記憶および古い版に対応する会話を除外する。

さらに、実際に補助知能へ渡した会話の生命循環IDを `dialogue-turn:ID` として記録する。関係や経験を含め、除外対象の応答を履歴として利用した後続応答も、依存関係をたどって除外する。文字列の一致だけに頼らず、言い換えられた情報にも対応する。現在入力と、除外情報に依存していない会話は引き続き利用できる。

物理削除では、対象記憶の元発言・利用応答・それらに依存する活動中文脈の本文も関係が伏字化する。その後、既存のチェックポイント整理とSQLite再構築を行う。生命循環の構造的証跡、保護監査および内容を復元できないダイジェストは保持する。

通常の記憶選択から外れる長文や入力予算外の訂正でも、統治履歴の対象IDから変更した会話を追跡して削除する。管理要求には本文を含まない `memory-governance-target:ID:v版` を記録し、取消済みの削除要求も、後に同じ対象の削除が確認されたときに伏字化する。操作の戻り値の生命循環記録も、追記後のCore正本と一致させる。

### 確認への短い回答

「コーヒーの淹れ方を説明して」への経験由来の確認に「温度です。」と答える場合、現在入力の語句だけでは関連記憶が選ばれない。その理由だけで元の質問まで除外すると、回答対象が補助知能へ届かない。

同じ相手・会話・経験版の直前に公開した固定確認をCoreが検証し、元の質問と固定確認の1往復だけを回答時の文脈へ保持する。今回非選択の記憶本文や、ほかの除外済み応答を追加しない。記憶の旧版・非活性化、関係の失効、管理操作による割込み、証跡不足の旧DBからは復帰しない。現在入力と選択材料を含めた上限へ収まらない場合も、確認参照IDだけを付けて通常応答へ進めず、経験が選ばれていれば確認を継続する。

### 保存失敗後の継続

文字入力で保存に失敗した後、時間イベントを呼ぶと、RAMに残った未保存の変更を別チェックポイントとして確定できた。時間イベントの入口でも永続化の健全性を確認し、失敗後は開始前に拒否する。文字入力、新しい会話、読み取り能力と合わせて停止し、再起動時に最後の確定状態へ戻る。

## 3. 旧DBの継続

新しい記録は既存の `RecordEntry` に保存し、保存形式の変更や構成版の更新を必要としない。生命識別、記憶・関係・経験の正本、確認待ちおよび活動中文脈をそのまま復元する。

段階17より前の会話には、依存情報を記録し終えたことを示す `dialogue-materials:v1` がない。その内容が忘却済み情報へ依存していないとは証明できないため、旧履歴は保存状態に残す一方、次の補助知能入力からは除外する。新たに記録した会話は通常どおり利用する。旧履歴をまたぐ物理削除では、関連範囲を限定できない旧ターンも伏字化する。このため、旧DBの直前会話の引継ぎと物理削除範囲は安全側に制限される。

## 6. 制約と次段階

- 対象は既知の一人と一つの活動中文脈であり、複数窓口・複数人・同一DBの同時使用は対象外。
- 長期記憶の関連性は決定的な文字照合で判定する。自由な意味検索や、任意の記憶の意味的重複・言い換えを独立した正本間で追跡する機能はない。
- 記憶の忘却は指定された記憶とその利用依存を対象とする。別途確認して登録した関係や経験は、それぞれの正規の撤回・不採用経路で変更する。
- 物理削除の対象は管理下のSQLiteと活動中文脈。OS側の複製、バックアップ、外部モデル側の記録や既に表示された文章は削除しない。整理失敗は部分完了として残存範囲を報告する。
- 本検証は入力・出力境界、有限な経験方針、権限不変性とデータ選択の検証であり、補助知能の自由な文章の正確性や任意の指示注入に対する完全な耐性を保証するものではない。
- 常駐、自発的発話、定期通知、自律的外部接触は追加しない。能力の通常会話からの自動選択、音声、身体表現も対象外。

次は段階18「対話窓口と相手識別」。既存の生命循環を通る追加窓口、話者・宛先・会話単位の識別、順序・重複・競合・再送を扱う。本段階で成立した情報統治と保護を維持することを前提とする。
