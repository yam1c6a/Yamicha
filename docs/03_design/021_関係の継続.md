# 関係の継続

## 1. 目的

本書は、実装ロードマップ段階15における関係情報の確認、訂正、撤回、限定利用および復元を定める。

相手の希望、合意、配慮事項、継続中の事項および距離について、相手が明示して確認した内容を会話の材料として継続する。通常の会話や一度の親しげな発言から、合意や距離を自動で確定しない。

## 2. 責務

| 責務 | 段階15で行うこと |
|---|---|
| 判断 | 明示的な関係情報の追加、確認、取消、訂正および撤回を要求へ変換する |
| 核 | 現在の入力と確定済み判断に対応する要求だけを関係へ渡す |
| 関係 | 相手、対象ID、対象版、確認状態、有効期間および適用範囲を検証し、正本と変更履歴を所有する |
| 補助知能 | 関係が選んだ現在有効な情報だけを、未信頼の会話材料として受け取る |
| 永続化 | 関係情報、確認待ちおよび変更履歴を同じチェックポイントに保存・復元する |
| 表示境界 | 保存された操作結果と確認待ちを表示し、一覧から訂正・撤回対象のIDを確認できるようにする |

Memoryの会話記憶と関係情報は別の正本とする。関係情報を記憶候補へ重複登録せず、関係に対する撤回がMemory経由で再利用されないようにする。

## 3. 情報の意味と権限

関係情報は、希望、合意、配慮、継続事項および距離の五種類とする。内容、相手、由来、根拠入力、確からしさ、確認状態、有効期間、再確認条件および版を持つ。

ここでの合意は、相手が確認した会話上の取り決めである。外部操作の事前承認、能力実行の権限およびYamicha自身の判断として扱わない。親しさや呼び方の希望によって、能力の許可対象、権限観測、外部効果ゲートまたは保護解除の条件は変化しない。

## 4. 対話操作

| 入力 | 結果 |
|---|---|
| `関係：希望：説明は短めに` | 希望の追加を確認待ちにする |
| `関係：合意：作業前に内容を相談する` | 会話上の取り決めを確認待ちにする |
| `関係：配慮：急かす言い方は避けてほしい` | 配慮事項を確認待ちにする |
| `関係：継続事項：旅行の予定を相談中` | 継続中の事項を確認待ちにする |
| `関係：距離：丁寧な呼び方を希望する` | 距離に関する相手の希望を確認待ちにする |
| `関係確認` | 現在の相手に属する確認待ちを確定する |
| `関係取消` | 確認待ちを取り消す |
| `関係訂正：ID：新しい内容` | 指定した版の訂正を確認待ちにする |
| `関係撤回：ID` | 対象の関係情報を通常利用から外す |

追加および訂正は、別の入力による確認を経て有効になる。`はい` のみでは関係情報を確定しない。これにより、段階14の物理削除確認と混同しない。

確認待ちは相手ごとに一件とし、既定の確認期限は24時間とする。有効期限がそれより早い場合はそちらを使う。期限切れや対象版の変更後は確定せず、内容の再提示を必要とする。`関係確認：確認待ちID` と `関係取消：確認待ちID` で対象を明示することもできる。

本文の末尾に ` | 話題=コーヒー,紅茶 | 期限=2026-10-28T00:00:00+09:00` を付けると、現在入力に指定話題が含まれ、有効期限前である場合に限定できる。話題は最大5個・各32文字で、本文は256文字までとする。省略時の追加は全会話・有効期限なし、訂正は既存の範囲と期限を引き継ぐ。`話題=全会話` と `期限=なし` で明示的に変更できる。

`説明は短めにしてほしい` と `詳しく説明してほしい` の完全一致入力も、希望の追加候補として確認待ちにする。その他の自然文を同じ意味だと推測しない。

撤回は物理削除ではない。正本の状態と版を変更し、変更履歴に理由と影響範囲を残す。

## 5. 判断と応答への限定利用

現在の相手に属し、確認済みで、有効期間と適用範囲を満たす情報だけを選択する。選択したID、版および理由を判断材料として渡し、補助知能へ渡す場合も会話文脈・会話記憶と区別する。

関係情報は最大5件・本文合計512文字までとし、現在入力を優先した全体文字数上限の中で利用する。関係情報の内容は命令、権限または外部事実の証明にならず、補助知能が関係情報の正本を更新することはない。

関係の管理入力とその応答は、次の補助知能呼出しに使う過去の会話文脈から除外する。また、通常の会話で判断材料に用いた関係ID・版を記録する。訂正・撤回・期限到達、話題変更または件数・文字数の上限によって、その関係情報が今回の補助知能向け選択に含まれない場合は、それを利用した会話ターンも補助知能用の文脈から除外する。これにより、古い版や上限から外した情報が過去の返答経由で戻ることを防ぐ。活動中文脈の保存記録そのものは変更しない。

管理入力への応答は補助知能の生成文に依存せず、確認待ち、完了、取消、不成立などの実際の操作結果を表示する。

関係・記憶の一覧と管理結果は、保護境界で通常出力の許可とチャネル権限を確認してから表示する。保護中または通常出力が無効な場合は、確認待ちや撤回済みの内容も表示しない。許可・拒否は本文を含めず監査へ記録する。

## 6. 継続と復元

構成版は `stage15-v1` とする。段階13または段階14の保存状態から、同じ生命識別、記憶、活動中文脈および保護状態を保って直接移行する。旧データに存在しない関係情報を推測で作らず、未対応の構成版からの移行は拒否する。

`/new`、再起動および補助知能モデルの交換を越えて、関係情報と変更履歴を維持する。確認待ちも復元する。保存失敗時は後続の変更を停止し、再起動後に最後の確定済みチェックポイントから復元する。

## 7. 品質ゲート対応

- 好み、合意および距離によって外部操作の権限や恒久的な同意が付与されないことを検証する。
- 追加・訂正の確認前、取消後、撤回後および期限切れの内容を有効な関係情報として使わないことを検証する。
- 訂正前後の版、理由、根拠および影響範囲を追跡する。
- 再起動、会話文脈切り替え、モデル交換および保存失敗からの復元を検証する。

## 8. 制約

- 初版は明示的な入力規則を用い、通常の発言やLLMの推測から重要な関係情報を自動作成しない。
- 複数人・複数窓口にまたがる関係は段階18以降の対象とする。
- 人間の後続反応から表現方針を学習する経験の対話反映は段階16の対象とする。
- 関係情報の撤回は通常利用からの除外であり、履歴本文やDB外の複製の物理削除を意味しない。

## 9. 検証

`tests/test_stage15_relationship_continuity.py` で、追加と確認の分離、全種別、確認待ちの復元、訂正・撤回、古い版に依存した会話の除外、期限と話題、重複と第三者入力、LLM停止・交換、権限不変、保存失敗からの復元、段階14のDB移行およびコンソール表示を検証する。

`python scripts/quality.py` を品質確認コマンドとする。対話試験には決定的なテスト用LLM応答を使い、実Ollamaによる自然な表現の品質評価はこの自動試験に含めない。

レビュー後の回帰試験では、保護中・再起動後・通常出力無効時の一覧と管理結果の表示拒否を追加した。`tests/test_stage15_upgrade_compatibility.py` は段階13からの直接移行、標準コンソール起動、保護状態の保持および未対応版の拒否を検証する。

2026年10月27日のレビュー修正後の確認では、構文・依存方向・UTF-8検査と全197件のテストが成功した。うち段階15の統合・移行試験は33件である。レビューで指摘された表示境界と移行互換性は、追加した回帰試験と再レビューでも修正を確認した。

同日の実Ollama確認では、一時DBに「説明は一文で短くしてほしい」という希望を登録・確認し、終了後の再起動で同じ生命識別と関係情報1件を復元した。「空が青く見える理由を説明して」に対し、この関係情報を含む要求が成功し、一文の応答を得た。既存の会話DBは使用していない。この一例は接続と反映経路の確認であり、あらゆる表現で希望が満たされることの保証ではない。
