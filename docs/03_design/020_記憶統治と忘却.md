# 記憶統治と忘却

## 1. 目的

本書は、実装ロードマップ段階14における会話記憶の確認、訂正、非活性化、再評価、論理忘却、物理削除、保持範囲およびチェックポイント世代整理を定める。

段階13で採用した会話記憶を、相手が内容と効果を区別しながら管理できるようにする。特に「通常利用から外した」と「保存媒体から本文を除去した」を同じ完了表現にしない。

## 2. 責務

| 責務 | 段階14で行うこと | 行わないこと |
|---|---|---|
| 判断 | 明示的な訂正、非活性化、再評価、物理削除と確認・取消を規則で判定する | LLMに記憶ID、対象版、削除完了を決めさせない |
| 核 | 統治要求をMemoryへ配送し、通常の生命循環外からの更新を許可しない | 本文を所有しない |
| Memory | 対象の相手、ID、版、活動状態を検証し、変更と統治記録を同時に作る | 曖昧な訂正を推測で適用しない |
| 関係 | 物理削除対象の活動中会話ターンを伏字へ置換する | 退役済み会話本文を別に保持しない |
| 永続化 | 正本確定、旧世代削除、WAL切詰め、VACUUMを行う | OSバックアップやDB外の複製を削除済みと主張しない |
| 表示境界 | 完了、不成立、確認待ち、取消、部分完了を補足表示する | LLMの自然文だけで操作結果を表現しない |

## 3. 操作モデル

統治操作は次の五種類を別の意味型として扱う。

| 操作 | 効果 | 本文の残存 |
|---|---|---|
| 訂正 `correction` | 同一記憶IDの版を上げて本文を置換する | 訂正履歴に訂正前後を保持する |
| 非活性化 `deactivation` | 通常検索から外す | 保持する |
| 再評価 `reevaluation` | 確からしさと理由を版付きで更新する | 保持する |
| 論理忘却 `logical_forget` | 相手の忘却要求として非活性化する | 保持する |
| 物理削除 `physical_delete` | 管理対象の本文を伏字へ置換し旧保存世代を除去する | 本文を保持せずSHA-256ダイジェストだけを残す |

各要求は要求ID、生命循環ID、相手、操作、対象IDと対象版、入力参照、理由、時刻を持つ。各結果は統治記録ID、変更前後の版、状態および残存範囲を持つ。訂正結果だけは訂正前後の本文と同一項目の置換関係を持つ。

## 4. 入力規則

- `コーヒーじゃなくて紅茶` は、関連する活動中記憶が一件の場合だけ、その記憶内の対象語を置換する。
- `訂正：コーヒーが好き → 紅茶が好き` は明示した新しい意味へ置換する。
- `猫を無効にして` は非活性化、`猫を確認済みにして` は確からしさの再評価として扱う。
- `猫を忘れて` は段階13と同じ論理忘却であり、物理削除とは扱わない。
- `猫を完全に削除して` または `完全に削除：猫` は物理削除の確認待ちを作る。
- 確認待ちに対する `はい`、`確認しました`、`完全に削除して`、`削除を承認します` だけを確認として扱う。`いいえ`、`やめて`、`キャンセル` は取消とする。
- 訂正候補が複数ある場合は変更せず、対象を一件に絞るよう表示する。
- 物理削除対象がない場合は不成立を記録し、確認待ちを作らない。

確認待ちはMemoryが相手ごとに所有し、SQLiteへ保存するため再起動を越える。単なる肯定表現を、確認待ちがない状態で削除承認へ読み替えない。

## 5. 一覧と説明

対話コンソールでは次の読み取り専用コマンドを提供する。

- `/memory`: 活動中の会話記憶を新しい順に表示する。
- `/memory all`: 非活性化済みおよび物理削除済みの墓標を含めて表示する。

各行には活動状態と版を表示する。物理削除後は元本文ではなく `[物理削除済み]` を表示する。

## 6. 保持・削除範囲

| 情報 | 保持方針 | 通常の忘却 | 物理削除 |
|---|---|---|---|
| 活動中会話文脈 | 一つの活動中文脈だけを正本化 | 変更しない | 対象由来ターンと削除確認ターンを伏字化 |
| 会話記憶候補・正本 | 明示操作まで保持 | 非活性化 | 本文を伏字化しダイジェスト化 |
| 訂正履歴 | 統治説明に必要な間保持 | 変更しない | 対象項目の訂正前後本文を伏字化 |
| 生命循環記録 | 構造的証拠として保持 | 削除不可 | 本文を含まないため保持 |
| 保護監査 | 改ざん検出証拠として保持 | 削除不可 | 削除不可 |
| 補助知能追跡 | 入出力本文ではなく範囲と出力ダイジェストを保持 | 変更しない | 保持 |
| SQLiteチェックポイント | 新しい二世代 | 直近二世代に自然整理 | 伏字化済み正本一世代を確保後、旧世代を削除して再構築 |

OSスナップショット、クラウド同期、手動コピー、ディスクの履歴、ログへ外部転記された内容はYamichaの管理範囲外であり、完了結果の対象に含めない。

## 7. 物理削除の確定手順

1. 明示要求を対象ID・版へ解決し、確認待ちとしてチェックポイントへ確定する。
2. 確認入力時に対象版を再検証する。古い版または別の相手なら不成立とする。
3. 記憶項目、由来候補、対象に関する訂正履歴、活動中文脈を伏字化し、本文ダイジェストを作る。
4. 伏字化済みの正本チェックポイントを先にコミットする。この時点の結果は部分完了であり、旧世代が残ることを明示する。
5. SQLiteトランザクションで旧チェックポイントを除去する。失敗時は削除前か削除後のどちらかに決定的に戻る。
6. WALを切り詰めてVACUUMし、DBファイルを再構築する。
7. 統治記録を完了へ更新した新しいチェックポイントを確定し、通常の二世代上限へ整理する。

旧世代削除またはDB再構築を確認できない場合、結果は `partial` のままとし「物理削除済み」と表示しない。ただし最新の復元正本では対象本文を通常利用しない。

## 8. 復元と構成移行

構成版は `stage14-v1` とする。`stage13-v1` からの移行では生命識別、既存の記憶、関係、保護状態、能力記録および補助知能追跡を維持し、統治記録と確認待ちは空で開始する。

確認待ち、訂正済み版、非活性状態、物理削除墓標、ダイジェスト、統治状態は再起動後も同じ内容で復元する。物理削除の世代整理中に停止しても、最後にコミット済みの伏字化正本から復元できる。

## 9. 品質ゲート対応

- 訂正前の版と論理忘却・非活性化済み項目は `active=False` のため通常検索と補助知能入力へ入らない。
- 物理削除は旧世代整理とDB再構築が完了するまで `partial` とし、削除済みと表現しない。
- 世代整理はトランザクションで行い、少なくとも最新のコミット済み正本を残す。
- 生命循環記録と保護監査は会話記憶操作の削除対象にしない。
- 物理削除後も本文の代わりにID、版、時刻、操作種別、状態およびダイジェストを残し、何が行われたかを本文なしで説明できる。

## 10. 残る制約

- 意味ベクトル検索は行わず、正規化文字列と二・三文字断片で対象を選ぶ。
- 複数の訂正候補から番号選択する専用対話は未実装であり、相手が対象を具体化する必要がある。
- DB外のバックアップ、複製、画面履歴および外部LLM側の記録は削除対象外である。
- 物理削除後のダイジェストは同一本文の照合材料になり得るため、本文そのものではないが機微度ゼロとは扱わない。
