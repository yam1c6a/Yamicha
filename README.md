# Yamicha

Yamicha を一つの生命として成立させるための設計・実装リポジトリです。

現在は、`docs/03_design/004_実装ロードマップ.md` の「段階16: 経験の対話反映」まで実装しています。

## 必要環境

- Python 3.11 以上
- 外部パッケージは不要
- 自然な応答には、起動中のOllamaと `gemma4:e4b-it-qat` が必要

## 対話する

リポジトリ直下で次を実行します。

```shell
python scripts/chat.py
```

入力欄に文字を入れると、段階16の「入力検証・権限確認 → 関係による会話文脈・確認済み関係情報の限定提示 → Memoryによる関連記憶・確認済み経験の限定提示 → 判断 → 核による補助知能利用の確定 → ローカルLLMの候補 → 判断と核による採否 → 言葉 → 出力境界 → 会話ターン・記録・候補評価 → 記憶統治・関係更新・経験確認 → 永続化・監査」を通った応答が表示されます。終了するには `/quit` を、新しい会話文脈へ切り替えるには `/new` を入力します。活動中の記憶一覧は `/memory`、無効化済みを含む一覧は `/memory all`、関係情報は `/relationship`、経験は `/experience` で確認できます。

パッケージをインストールした環境では、次のどちらでも起動できます。

```shell
yamicha
python -m yamicha
```

状態、生命循環記録、記憶候補、経験候補、採用された記憶、会話由来の長期記憶、その統治記録と確認待ち、関係情報と変更履歴・確認待ち、確認済み経験と証拠・変更履歴・利用履歴・確認待ち、活動中の会話文脈、保護状態、生命識別、構成版、保護監査、能力の重複防止記録および補助知能の追跡記録は `.yamicha/yamicha.sqlite3` に保存され、次回起動時に復元されます。段階13・14・15のDBは同じ生命識別と既存情報を保ったまま段階16構成へ直接移行します。別の保存先は `python scripts/chat.py --db <パス>` で指定できます。

段階9では、核が統合した要求だけを受けるUTF-8テキストの読み取り専用能力を追加しています。対象、操作、権限、想定効果、重複防止キーを検査し、成功・失敗・部分成功・結果不明を感覚へ返します。同じ重複防止キーは、結果不明の場合も自動再実行しません。通常の対話から能力を選択する処理はまだ実装していません。

段階10では、現在の検証済み入力だけをOllamaへ渡し、返された文章を未検証の表現候補として扱います。補助知能は画面上の話者にならず、Yamichaの発話候補だけを作ります。候補は判断の確認と核による自己同一性・採否の検査を経て、言葉の一致検査と出力境界を通過した場合だけ表示されます。Ollamaの停止、タイムアウト、不正出力または制約違反時は、既存の定型応答へ戻って生命循環を継続します。

段階11では、段階10の実行構成を対象にYMC-T01からYMC-T10までの統合試験を追加し、最小構成への適合を確認しています。承認済み経験は変更対象・変更前後・理由・再評価条件を伴って次の判断材料へ反映され、再起動時には停止中の経過時間も内部時間へ加算されます。適合結果と制限は `docs/03_design/016_最小構成適合.md` に記録しています。

段階12では、関係が検証済みの人間入力と実際に公開したYamichaの発話を活動中文脈として所有します。現在入力を優先し、直近6往復以下かつ本文合計4,096文字以下を、毎回明示的な `user` / `assistant` メッセージとして補助知能へ渡します。LLM側のセッションには依存しません。活動中文脈は再起動後も復元され、`/new` で新しい文脈へ切り替えられます。詳細は `docs/03_design/018_会話文脈.md` に記録しています。

段階13では、`覚えて：内容`、`私はコーヒーが好き`、直前質問への `モカかな`、`コーヒーのこと忘れて` のような明確な表現をルールで処理します。ルールに一致しない自然な好みや忘却表現は、ローカルLLMが `remember / forget / none`、本人性、意味、対象、確からしさ、確認要否および現在入力からの根拠引用を持つ未信頼候補として構造化します。LLMは記憶IDや更新を決めず、判断・核・Memoryが第三者情報、曖昧さ、根拠、対象件数および版を検証した場合だけ反映します。採用済み記憶は `/new` と再起動を越えて保持され、関連する場合だけ最大5件・本文合計1,024文字まで補助知能へ提示されます。詳細は `docs/03_design/019_会話記憶.md` に記録しています。

段階14では、`コーヒーじゃなくて紅茶` または `訂正：旧内容 → 新内容` で一件の記憶を訂正し、訂正前後、対象版、理由、要求元および置換関係を記録します。論理忘却、非活性化、再評価、物理削除は別の操作として扱います。`コーヒーを完全に削除して` は直ちに実行せず、再起動を越えて保持される確認待ちになり、続けて `はい` と入力した場合だけ本文を記憶候補・正本・活動中文脈・旧チェックポイントから除去し、SQLiteを再構築します。結果は完了、不成立、確認待ち、取消、部分完了を区別します。詳細は `docs/03_design/020_記憶統治と忘却.md` に記録しています。

段階15では、`関係：希望：説明は短めに` のように希望・合意・配慮・継続事項・距離を明示し、別の入力で `関係確認` と答えた場合だけ関係情報として保存します。`関係取消` で確認待ちを取り消せます。`/relationship` でIDを確認し、`関係訂正：ID：新しい内容` とその確認で更新、`関係撤回：ID` で通常利用から除外できます。確認済みで現在の話題と有効期間に合う情報を最大5件・本文合計512文字まで対話へ渡し、好みや親しさから外部操作の権限を付与しません。`/new`、再起動およびLLMの交換後も関係情報と履歴を保持します。詳細は `docs/03_design/021_関係の継続.md` に記録しています。

段階16では、応答後の `経験：直前：長すぎた`、`経験：直前：説明が足りなかった`、`経験：直前：確認してから答えてほしかった` を確認待ちにし、別入力の `経験確認` によって応答文字数の制約や回答前の確認へ反映します。`経験取消` で確認待ちを取り消せます。既定では同じ相手・同じ会話文脈に限り、` | 話題=コーヒー` を明示した場合だけその語句を含む会話へ再利用します。`/experience` でIDを確認し、`経験見直し：ID：反応` または `経験不採用：ID` と別入力の確認で更新します。通常の後続発言、沈黙やLLMの評価だけでは方針を変えず、証拠、変更前後、理由、適用範囲および利用した版を保存します。詳細は `docs/03_design/022_経験の対話反映.md` に記録しています。

意味ベクトル検索、複数候補を対話で一件へ絞る機能、OS・ストレージ側のバックアップや複製の削除、読み取り能力の自動選択は未実装です。物理削除はYamichaが管理するSQLite正本とそのチェックポイント世代を対象とし、生命循環の構造的証拠、保護監査、内容を持たないダイジェストは削除しません。

## 品質確認

リポジトリ直下で次を実行します。

```shell
python scripts/quality.py
```

このコマンドは、構文コンパイル、依存方向検査、UTF-8検査、単体テストを順に実行します。
